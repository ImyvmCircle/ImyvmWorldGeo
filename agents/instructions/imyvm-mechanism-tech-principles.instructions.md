# IMYVM 机制技术原则

1. 实现或改动资源发放、资源收取、跨模块入账或扣款机制时，区分账户型资源和物品型资源。账户型资源通过账户 API 变更余额；物品型资源通过物品发放或扣除处理。资源操作使用统一资源栈或等价抽象表达，发放与收取接口返回结构化结果；涉及账户、组织资产或外部系统资产变动时记录流水编号。账户扣款保持原子性，余额不足返回明确失败；物品扣除按物品 ID、自定义名称、lore、附魔和 NBT 严格匹配。
2. 实现或改动结算机制时，将事实冻结与资源转移分为两个阶段。冻结阶段确定主体、数量、来源、周期等事实并写入不可变结算记录；执行阶段只调用资源或账户写入。执行失败时保留待处理状态，重试沿用冻结事实，不重新计算、不重新随机。
3. 实现或改动金钱与实物机制时，必须明确在线与离线边界。账户型金钱统一通过公开账户 API 取得钱包并变更余额；在线玩家使用服务器提供的真实 `Player`，离线玩家使用调用项目构造的轻量 `Player` 代理。代理携带目标 UUID 和最后已知名称，不加入世界、在线玩家列表或网络连接。玩家在线状态不参与账户结算判断，登录事件可以作为额外核对触发。实物消费与兑换仅扣除在线玩家背包，玩家离线时按业务规则拒绝或进入待领取记录。
4. 实现或改动账户事务、失败重试、待处理记录或补偿机制时，由调用项目保存幂等与恢复依据，不假定账户项目提供离线事务。事务记录必须保存周期编号、主体 UUID 及名称、资源、金额或数量、来源、外部引用、前序阻塞事务、失败阶段、失败原因、重试次数和下次重试时间；每次账户写入另存尝试编号、尝试时间、变更前余额、预期余额和外部写入调用边界。账户事务使用 `DETERMINED`、`SUCCEEDED`、`PENDING`、`NEEDS_OP` 和 `RESOLVED` 状态。外部写入前先持久化调用已开始标记。启动恢复时，没有调用已开始标记的事务重新读取当前余额并安全执行；存在调用已开始标记时，当前余额等于预期余额可以自动确认，变更前余额不构成自动重放证据，其他结果进入 `NEEDS_OP`。同一账户的调用项目写入按事务顺序串行；前序事务进入 `SUCCEEDED` 或 `RESOLVED` 前，后续事务保存确定事实并引用前序阻塞事务，不调用账户 API，也不累计技术重试次数。事务排到首位或执行尚未调用账户 API 的安全重试时，重新读取当前余额并追加本次写入尝试，已确定的金额、数量和来源保持不变。该顺序约束不限制玩家或其他项目发起的账户活动。能够证明外部写入尚未发起的技术故障在 10 秒、1 分钟和 5 分钟后依次重试，第三次失败后进入 OP 异常收件箱。组合资源操作另存有序步骤，每步保存独立外部引用、完成证据和补偿引用；账户状态与业务步骤进度分开。事务与审计采用追加式分段记录，内存保留未解决项和近期索引，历史分片保持只读，持久聚合值代替全历史扫描。OP 登录时提示未解决异常，并通过主体名称、业务对象名称、可读短编号、点击入口和命令建议完成处理；人工处理不要求输入 UUID 或内部事务编号。原事务与审计记录不得删除。实现文档不得要求调用项目直接修改账户数据库。
5. 实现或改动周期结算、定时结算或周结束任务时，所有结算记录必须携带周期编号与交易流水编号，用于对账、幂等和重复执行防护。周期边界以 WorldGeo 时间服务为准，默认按东八区计算。WorldGeo 1.5.6提供周期编号、周期起止时间、可用周期枚举、不可变快照和持久统计检查点。周期回调用于唤醒检查，周期事实通过不可变快照、可用周期枚举和检查点交付；调用方持久化独立消费游标，在本地事务完成后推进游标。服务器启动时按消费游标补算错过的周期，不重复结算同一周期。调用方启用新周期机制或绑定新业务对象时保存检查点，从检查点后的当前周期增量开始结算；检查点之前的统计不生成调用方结算结果。周期统计采用流式或分片写入，经临时文件、完整性校验和原子发布后生效；写入失败保留上一完整版本，进程存活时保留待写变更，条目容量不得触发提前淘汰或静默丢弃。异常进程终止可以丢失最近一次成功保存后的统计，丢失窗口不超过配置的保存间隔，默认约 1 小时；保存失败后默认每 1 分钟重试。周期关闭、检查点、容量告警和正常停机必须触发强制保存。小时、日、周统计在周期结束 2 个自然月后到期，月统计在周期结束 1 年后到期，年统计永久保留；到期时间按东八区计算，清理以完整周期分片为单位，检查点按来源周期保留期清理，到期查询必须返回明确不可用状态而不是空统计。周结束行为纳入统一任务管理，具体任务由所属项目定义；下层项目不得列举上层玩法任务。
6. 实现或改动玩家交互、菜单 lore、提示、公告、日志下行或结算反馈消息时，必须先与用户确认消息分层：哪些消息所有玩家可见，哪些只对对应管理者与 OP 可见，哪些仅 OP 可见，哪些属于系统私有信息。该分层只影响信息发送，不改变业务权限判断。系统私有参数只允许存在于服务端持久化、配置或内部计算中，不得出现在任何下行消息、菜单 lore 或玩家提示里；系统私有参数包括随机种子、精确公式、风控阈值、反刷权重或同类实现细节。
7. 实现或改动跨项目机制时，下层项目不得出现上层业务语义；上层项目只能通过下层公开 API 组合能力，不直接依赖下层的 `infra`、`application` 或 `mixin` 包。与 Minecraft 原版代码的交互应集中在各项目的 `infra` 或 `entrypoint` 层；能用 Fabric API 完成时优先使用 Fabric API，只有在公开 API 不足以表达目标行为时才考虑 mixin。
